# HealthLink Studio · 디자인 시스템 1.0.0 적용

기준 커밋: `fe3ea693e6803d3ed9bd5e91cf2c3a26b50fb704` (v0.3.5).
사용자 첨부 `HA_Component_Design_System_v1.0(2).zip`의 Wallet v1.11.0 기준을 적용한다. 기존 작은 카드 대시보드의 12/10/8px 규칙은 새 가이드의 24/19/12px 체계로 대체한다.

## 화면 구조

| 영역 | 내용 / 이전 기능 대응 |
|---|---|
| 한눈에 | 한 개의 어두운 수신 기록 요약, 직접 정한 목표, 개인 기준선 비교, 수신 상태로 이동 |
| 건강 데이터 | 실제 수신 목록, 이름·ID·영역 검색, HA 노출 필터, 노출 설정, 조합 센서 목록·삭제 |
| 기록·분석 | 기존 타임라인과 인사이트를 두 조회 방식으로 통합. 기간·집 센서·연관 분석 방향 유지 |
| 연결 | 수집 활성화와 실제 수신을 구분. 기존 Companion 안내, Apple 기기 선택, ECG·원본 가져오기 설정 경로 유지 |
| 센서 만들기 | 건강 데이터 화면의 주 행동. 오른쪽 580px 네이티브 dialog, 좁은 화면에서는 전체 폭 |

설정·프로필 추가는 HA의 기존 네이티브 통합 화면으로 이동한다. Studio가 Options Flow를 대체하지 않는다. 프로필이 여럿일 때만 선택기를 표시하고 모바일에서는 독립된 행으로 배치한다.

## 디자인 값과 업무별 조정

최대 래퍼는 패딩 포함 1248px, 기본 좌우 40px, 870/560/350px 이하에서 28/20/16px이다. 컨테이너 쿼리를 사용한다. 제목 38/28px, 본문 15px, 보조 글자 최소 12px, 입력 16px·최소 46px, 조작 영역 최소 44px을 사용한다. 주 버튼은 다크에서도 #2563eb/흰색을 유지한다. 필드 경계는 공통안의 접근성 보완값 #8490a2를 사용한다.

건강 기록 요약은 복권 번호 대신 실제 항목 수·기록 수·최근 수신을 보여준다. 한국어 설명이 끊기지 않도록 데스크톱 요약의 첫 열은 최소 280px(중간 폭 240px)로 조정했다. 카드 제목 18px, 상태 문구와 목표 목록을 우선하며 장식용 그래프나 임의의 건강 판정을 넣지 않는다.

## 보존한 서버 계약

서버·DB·센서·이벤트·의료 분석·민감 항목 정책은 변경하지 않는다. Python 변경은 Studio 엔트리 URL에 `&ui=20260913.1`을 붙이는 한 줄뿐이다. manifest와 VERSION은 0.3.5 그대로이며 새 릴리스를 만들지 않는다.

기존 `hass.callWS` 경로를 사용한다: `health_link/status`, `catalog/list`, `catalog/expose`, `composer/list`, `composer/validate`, `composer/save`, `composer/delete`, `timeline/query`, `insights/correlation`, `optimizer/observe` (앞의 health_link 접두어 공통). 각 대상 요청에 캡처한 config_entry_id를 전달한다. 타임라인은 24시간/7일/30일, 연관 분석은 30/60/90/180일과 high/low를 유지한다. 계산식 a, (a+b)/2, a+b, a-b, ratio(a,b), a*b와 입력/단위/icon 계약을 유지한다.

원본 `health-link-panel.js`는 수정하지 않고 보관한다. Studio의 기존 modern 엔트리는 뷰 모듈을 가져오는 독립 컨트롤러로 교체한다. 같은 `health-link-panel` 요소명과 `/health-link-studio` 경로를 유지한다. 원본 로고 `frontend/brand/logo.png`도 그대로 사용한다. Git blob `5647226142f5b85f69e3c6f280b9337d6dce7278`은 변경 대상이 아니다. 로고 토큰 요청은 필요 없는 번들 내부 공개 이미지 경로를 사용하며, 로고 실패 시 이름으로 대체한다.

## 상태·입력·접근성

미수신/unknown/null과 실제 0을 구분한다. `last_sync`는 수신 시각, 별도의 시각은 상태 확인 시각으로 표기한다. Companion 수집 활성화를 실시간 기기 연결이라고 부르지 않는다. 서버 상태 실패에는 마지막 값이 최신이 아닐 수 있음을 표시한다. 카탈로그와 조합 센서 조회, 두 분석 결과의 부분 실패를 각각 처리한다.

조회 결과는 최대 최근 300개와 응답 전체 개수를 표기한다. 기존 2,500개 수치형 집 센서 후보 제한도 초과 시 표시 범위를 알린다. 기존 Companion의 `timestamp_unavailable` 제한을 우회하지 않는다. 상관 분석은 원인·의료적 효과·자동 제어 권고가 아니다.

초안은 해당 dialog DOM 안에서 유지한다. 배경 갱신은 편집 중 건너뛰며, 수동 갱신도 dialog를 재생성하지 않는다. 닫기/Escape/배경 클릭 시 미저장 입력을 확인한다. 전송 전 닫으면 저장을 보내지 않고, 전송 후 닫아도 서버 요청은 취소되지 않는다고 알린다. 저장 성공을 받은 뒤에만 완료를 표시하고 HA 센서 실체 반영과 구분한다. 뒤늦은 읽기·저장 응답이 다른 프로필을 덮어쓰거나 닫은 패널을 다시 열지 않도록 한다.

탭은 roving tabindex, 좌우/Home/End, 정확한 aria-controls/labelledby를 사용한다. 모달은 showModal의 배경 inertness와 명시적인 Tab/Shift+Tab 순환을 사용한다. 스크롤 잠금은 소유한 .hc-root만 대상으로 하고 HA/body 스타일은 변경하지 않는다. 오류는 패널 안에서 읽히며, 값은 escaping 후 렌더링한다. 재시도 시 동일한 전역 오류를 매번 새 alert로 만들지 않는다. 실제 스크린리더 동작은 별도 검증이 필요하다.

## 검증과 알려진 한계

`python tests/frontend/studio_browser_checks.py`는 Chromium+Playwright가 필요하다. CHROMIUM_PATH로 실행 파일을 지정할 수 있다. 실제 운영 모듈을 가상 HTTP 응답으로 제공하고 HA API 경계만 예시로 대체한다. 26개 테스트, 라이트/다크 각각 17개 폭(320~1440px), 360px 높이 모달, 768px 콘텐츠 폭 컨테이너를 검사했다. 기존 CI의 Python 수집에 Playwright 의존성을 강제하지 않도록 파일명은 test_로 시작하지 않는다.

기존 Node 테스트의 처음 6개는 그대로 유지하고, 이전 디자인을 고정한 마지막 2개만 새 뷰/토큰/라우트 규칙으로 업데이트했다. 새 뷰 구문 검사도 추가한다. 전체 HA Python/기존 Node 회귀 검증의 로컬 실행은 수행하지 않았다. 실제 HA, HACS 설치, 기기 제어, Safari/VoiceOver/NVDA, iOS 가상 키보드·안전 영역, 브라우저 확대는 미검증이다.

중요: composer/save는 서버 upsert이고 원자적인 create-only/revision 계약이 없다. UI는 현재 목록 및 저장 직전 최신 목록으로 ID 충돌을 막지만, 최신 조회와 실제 저장 사이 다른 클라이언트의 동시 생성까지 원자적으로 막지는 못한다. 완전한 충돌 방지에는 별도의 서버 계약 변경이 필요하다. 프로필 자체가 제거되거나 권한이 회수되면 보호를 위해 편집을 종료하고 데이터를 비운다. HA 내부 라우트 이탈은 브라우저 beforeunload의 보장 범위 밖이므로 초안 보존을 보장하지 않는다.

독립 미리보기는 예시 데이터이며 실제 건강 기록·HA 설치 확인 증거가 아니다. 작업 환경에서 로고 바이너리를 내려받지 않아 캡처는 텍스트 대체 상태이다. 실제 로고 비율·렌더링은 설치 후 확인해야 한다. 외부 폰트, 분석 스크립트, 런타임 패키지를 추가하지 않았다.
